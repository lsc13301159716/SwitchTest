# 10～30分钟交换机测试判据建议

日期：2026-10-12。当前范围为两台现有PC、单流、软件UDP测试。用户尚未确定验收阈值，已确认先做10～30分钟，30天后续考虑。本文件是建议稿，不把旧AI文档的经验阈值当成已经约定的验收标准。

## 推荐选择

建议以“有效测试中观察到零失败”为通过目标，把旧文档的0.001%改为“需要复核的孤立事件上限”，而不是有异常也直接PASS。原因是现有USB端点和软件调度可能引入伪影，但不能在没有证据时把它们一律扣掉。

RFC2544的吞吐测试采用发送与收到帧数相等的无丢失条件，但本项目普通PC测量并非完整RFC2544仪表测试。零失败目标是本项目的工程建议，不宣称RFC规定本项目的验收阈值。参考：[RFC2544 §26.1](https://www.rfc-editor.org/rfc/rfc2544.html#section-26.1)。

## 每轮结果分为四类

| 结果 | 建议规则 | 对设备意味着什么 |
| --- | --- | --- |
| PASS（本轮通过） | 测试有效且完成；本地发送失败=0；按预先固定timeout统计的超时/未回包=0 | 在本轮条件下未观察到异常，不证明所有负载或长期运行均无异常 |
| REVIEW（待复核） | 测试有效；有失败但全为孤立事件；失败比例<=0.001%；无本地发送失败 | 不能直接算通过或拒收；需定位、直连/原装对照与重复测试 |
| FAIL（本轮不达标） | 测试有效；连续失败>=2包，或失败比例>0.001% | 本轮不达标，但不自动把原因归给交换机 |
| INVALID（不能用于设备判定） | 明细不完整、正式测试未完成、已确认服务端提前停止，或用于比较的关键配置不一致等 | 保留原始证据并重测；不能用零指标填PASS |

本地发送失败单独列明并阻止直接PASS，先排查端点连接、路由和发送缓冲。若它发生在明确的故障注入用例中，应作为故障记录解释，不可静默删掉。

0.001%是来自旧文档的暂定复核界限，不是标准规定或从当前机器严格推导出的容限。若最终合同或业务规范规定0丢包，则REVIEW状态必须完成复核，不能自动放行。两次独立复测都没有再出现事件，也不能倒推首次失败一定由端点引起。

按序号完整记录的失败均保留。迟到包仍计入超时失败，同时记录完整迟到RTT。不要为得到PASS逐轮放宽timeout；门槛应在比较前固定。

## 时延采用相对评价

- 同一套电脑、网卡、线缆及收发角色，分别测试直连、原装、国产。相同帧长、发包间隔、duration、timeout、服务端模式、GC设置和输出方式。
- 输出p50/p90/p99、裁尾最大0.1%、原始max，以及迟到数量与最大迟到RTT。分位数和裁尾算法固定并写入报告；仅对按时RTT统计时须明确样本被timeout截断。
- p50/p90的国产/原装与国产/直连倍率都显示。直连用于判断测量底噪，原装才是替换对象；不能只与直连比就得出可替换。
- 任一主体分位数持续达到同条件参照的1.5倍，可暂列“明显劣化、需复核”。这是建议的调查触发值，不是经业务确认的硬验收线；1.49倍也不自动合格。
- 出现差异至少做交替重复测量，先用3组原装/国产配对复测判断是否稳定出现；3组只是初步复核，不宣称统计显著。
- 裁尾最大用于辅助对比，不能取代真实业务的最坏响应时间要求。原始异常始终保留。

timeout需同时兼顾业务能接受的停顿与直连测量端自身噪声。若测量噪声大于业务时限，应改善或标注测量能力不足，不能直接放宽门槛后宣称满足业务时限。旧文档0.5/0.3/0.15秒可作为历史诊断参数，不能自动成为PLC业务合格线。

## 当前阶段执行顺序

1. 记录两端有线IP、网卡类型、实际协商速率、设备标称速率、版本哈希、接线。检查工具可用及预热回显。NetCheck是可选辅助，Windows界面和人工记录也可提供这些证据。
2. 单流对64/512/1518字节帧做同参数直连、原装、国产各10分钟；没有异常或异常已得到解释的重点轮次再延长到30分钟。选定速率应在端点能力之内，与业务负载相符。
3. 全口做短测。B固定1号口，A测试2～16；再B改2号口，A测试1号口。首、中、尾与生产使用口选作10～30分钟重点测试。每轮保存端口对，不用文件名代替拓扑记录。
4. 任何失败保留包号、实际发送时刻、状态和现场动作，做对照复核。降速仅提供负载相关证据，不直接给端点或交换机定责。
5. 初步通过后结合真实业务掉站/报警记录评估替换。环网、电源、管理计数器按实际设备能力另列适用性；30天老化本阶段不执行。
