## 统计定义与兼容性

1. 当前 echo 的失败比例包含本地发送失败、超时后迟到、截至观察结束未回包。它反映应用层回显在门槛内是否完成，不单独证明交换机转发丢包。
2. 项目若继续将“连续失败段”称为“链路中断次数”，应在判据说明中明确这是项目定义的代理指标。工具数值可以对应，物理归因仍需另外证据。
3. 当前使用用户指定 timeout，不再隐式放宽。因此现场配置若保留文档建议的 0.5/0.3/0.15 秒，应显式传入，并以直连实测验证；这些值尚未作为确认后的需求写入默认配置。
4. 当前主 CSV 的 `late_rtt_us` 为完整 RTT。旧文件的 `late_us` 从“判超时的时刻”开始计算。两者不能直接比较，也不能对新版数值再次加 timeout。
5. 当前 `.late.csv` 附件仍沿用 `late_us` 列名，但内容已经变为完整 RTT。这是兼容性风险：历史 late_probe/loss_trace 等工具可能误读。后续宜明确版本并使用 `late_rtt_us` 列名或元数据声明；本次只记录问题，未改代码。
6. 主 CSV 原列仍可被按列名读取的旧工具使用，但未取得旧工具源码，无法确认其列数、命名和语义假设。仅有代码回归测试并不能证明历史工具兼容。
7. 自动 PASS 还应先检查有效数据、测试完成状态、配置可比性和所需端口覆盖。空数据或少测/失败的流不能因为数值为零就被判合格。

### 需要纠正的文档内容

- 老方案要求 0 丢包，较新的基线文档允许 <=0.001% 孤立失败；不能把两者同时作为统一的正式 PASS 规则。时延也有 RTT 最小、p50/p90、1.5倍报警等不同口径。建议见《短时测试判据建议.md》，目前属于建议，尚非已批准的合同指标。
- 基线文档说明判读工具可独立读取 CSV。因此“主程序没有 p50/p90”本身不是不满足设计；当前真正缺少的是交付完整的判读工具与可追溯参数。
- 参考端固定在1号口时，被测端不能也插1号口。可先固定B在1号口、A轮换2～16，再改B到2号口、A测1号口，记录每一对实际端口。
- 全口短测与抽样长测仍合理，但“1000pps满速长测”的称呼不准确。按当前未带VLAN的估算线速口径，1000pps 的64/512/1518字节帧分别约为0.672/4.256/12.304Mbps（请求方向），不是100Mbps或1Gbps线速。echo还有回程流量，且回显长度不同。
- 100Mbps是否异常须对照设备标称与实际连接，不应一律要求1Gbps，也不应把网卡旧脚本的千兆阈值直接变成验收门槛。
- 非网管现场不能要求必须提供管理计数器或镜像口。环网、冗余电源等项按设备实际能力和替换需求确认适用性，不凭旧方案自动启用。
- 降速后恢复不能单独证明端点过载；换口后恢复也不能证明端口故障。另一次测试没有再丢同一包号，无法证明上一次那个包只迟到。所有原始失败均保留，不能先剔除再宣称通过。
- 裁尾最大是去除尾部后的统计量，可辅助比较主体分布；不能宣称它是真实最坏时延。完整 max 与迟到事件仍须保留供排查。
- 基线文档称“60万包允许5个”不适用于正好600,000包：0.001% 对应6个；570,738包才是floor(5.70738)=5个。判读工具应按实际样本数计算。

旧方案命令50pps连续30天，名义样本数为129,600,000。当前EchoLedger将records、发送时间、状态等全留内存，CSV到结束才写，因此不适合直接运行此命令，也无法在进程故障后保住完整原始记录。
